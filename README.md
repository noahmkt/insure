# 내보험 찾기 (가칭) — 실손보험 청구 간소화 앱

> **"내가 놓친 보험금을 찾아주고, 청구까지 가장 쉬운 길로 안내하는 B2C 앱"**
> 청구 '실행 도구'가 아니라 청구 **발굴·안내·관리 레이어**. 실행(최종 제출)은 공식 채널(실손24·보험사)에서 고객 본인이 수행한다.

## 법적 하드 룰 (요약 — 전체는 docs/01-prd.md §3)

이 코드베이스의 어떤 변경도 아래를 위반할 수 없다:

1. **청구 대행 금지** — 최종 제출은 고객 본인. 성공보수 수취 금지.
2. **주민등록번호 원문 저장 금지** — CI 기반 식별. 스크래핑용 주민번호는 pass-through(메모리 사용 후 즉시 폐기, 로그·백업 미저장).
3. **민감정보 별도 동의** — 진료내역은 분리 동의 + 암호화 + 역할 기반 접근통제.
4. **동의 4층 분리** — 수집·이용 / 민감정보 / 제3자 제공 / 마케팅. 포괄 동의 금지.
5. **목적 외 이용 금지** — 청구 지원용 진료내역을 보험 영업에 사용 불가.
6. **모집행위 규제 준수** — "상품 권유"가 아닌 "전문가 상담 신청" 프레임.
7. **예측액 면책 문구 고정 노출** — "실제 지급액은 보험사 심사에 따라 달라질 수 있습니다."

코드 레벨 반영:

- 백엔드 전역에 주민번호 패턴 마스킹 로그 필터(`backend/src/common/logging/rrn-mask.ts`) 적용, DB 스키마에 주민번호 컬럼 자체가 존재하지 않음.
- 확정액(`ConfirmedBenefit`)과 예측액(`EstimatedRefund`)은 타입·테이블·API 응답 구조 수준에서 분리되어 혼용이 불가능.
- 예측액 응답 DTO는 `disclaimer` 필드가 항상 포함되도록 직렬화 단계에서 강제.
- 제3자 제공 동의(`THIRD_PARTY`)가 없는 사용자의 상담 신청은 API 레벨에서 409로 거부.

## 빠른 시작 (백엔드)

```bash
cd backend
npm install
npm run build        # TypeScript 컴파일
npm test             # 담보 매칭 엔진 등 단위 테스트
docker compose up -d # PostgreSQL (로컬 개발)
npm run start:dev
```
