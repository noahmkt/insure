# 네이버 노출 실행 가이드

네이버 서치어드바이저 공식 웹마스터 가이드와 네이버 검색 공식 블로그를 기준으로 정리한 실행 절차입니다.
**사이트 코드에 이미 반영된 항목**과 **배포 후 사람이 해야 하는 항목**을 구분했습니다.

> 전제: 네이버 웹 검색에는 "검색 등록 절차"가 존재하지 않습니다. 서치어드바이저 등록은 노출의
> 전제조건이 아니라 리포트 조회·수집요청·사이트맵 제출 등 **관리 도구**를 쓰기 위한 절차입니다.
> 또한 수집 성공이 곧 색인이나 노출을 뜻하지 않습니다 (수집 → 정제 → 색인 → 랭킹의 4단계).

## Phase 1. 수집 가능하게 만들기 — ✅ 코드에 반영 완료

이 단계가 막히면 이후 모든 작업이 무의미합니다.

| 항목 | 상태 | 구현 위치 |
|---|---|---|
| `robots.txt` 200 + text/plain 응답 | ✅ | `scripts/build.mjs` → `dist/robots.txt` |
| `User-agent: Yeti` 허용 | ✅ | 네이버 검색로봇 명시 허용 |
| JS·CSS·이미지·파비콘 경로 미차단 | ✅ | `Disallow` 규칙 자체를 두지 않음 |
| 생성형 AI 크롤러 허용 | ✅ | GPTBot·ClaudeBot·PerplexityBot·OAI-SearchBot |
| `noindex` 오설정 없음 | ✅ | 404 페이지에만 의도적으로 적용 |
| 단일 문서 1분 이내 / HTML 4MB 이내 | ✅ | 정적 HTML, 페이지당 수십 KB |
| HTTPS | ✅ | GitHub Pages 기본 제공 |
| 실제 404 상태코드 반환 | ✅ | `dist/404.html` (GitHub Pages가 404로 응답) |

> ⚠️ `robots.txt`가 **5xx로 응답하면 네이버는 전체 수집 비허용으로 해석**합니다. 파일이 아예 없으면
> 전체 허용이므로, 서버 오류로 5xx가 나가는 상황이 가장 위험합니다.

> ⚠️ 방화벽·CDN에서 검색로봇을 **IP로 차단하지 마세요.** 네이버 IP 대역은 변경됩니다.
> 검증이 필요하면 역DNS(`.naver.com` 확인 후 정방향 재확인)를 사용하세요.

## Phase 2. 등록·피드 — 🙋 사람이 해야 함

### 2-1. 서치어드바이저 사이트 등록

1. https://searchadvisor.naver.com 접속 → 웹마스터 도구 → 사이트 등록
2. **정식 호스트를 정확히 입력합니다.** scheme·www 유무·포트가 다르면 별개 사이트로 인식됩니다.
   - 이 사이트: `https://noahmkt.github.io` (커스텀 도메인 연결 시 그 도메인)
   - HTTPS 사이트를 HTTP로 등록하면 사이트 상태 리포트에서 "확인필요" 처리됩니다.
3. 소유확인 → **HTML 태그** 방식 선택 → 발급된 content 값을 복사

### 2-2. 소유확인 코드 입력

`site.config.mjs`의 `verification.naver`에 값을 넣고 다시 배포하면 전 페이지 `<head>`에 삽입됩니다.

```js
verification: {
  naver: '여기에_발급받은_값',
  google: '구글_서치콘솔_값',
}
```

> 소유확인은 JavaScript를 실행하지 않습니다. JS·`meta refresh`·쿠키 기반 리다이렉트는 지원되지 않고,
> `<frame>` 내부나 `<body>` 안의 메타태그는 검증에서 제외됩니다. 이 사이트는 정적 HTML의 `<head>`에
> 직접 넣으므로 해당 문제가 없습니다.

### 2-3. 사이트맵·RSS 제출

요청 > 사이트맵 제출에 아래를 입력합니다.

- 사이트맵: `https://noahmkt.github.io/insure/sitemap.xml`
- RSS: `https://noahmkt.github.io/insure/rss.xml`

제약: 소유확인한 도메인과 동일 도메인, 10MB 미만, 파일당 URL 50,000개 미만.
네이버는 사이트맵·RSS를 **콘텐츠 피드로 간주해 주기적으로 재방문**합니다.
공식 권고는 RSS보다 **사이트맵을 우선 활용**하는 것입니다(RSS는 본문을 포함해 URL 수용량이 적음).

### 2-4. 수집요청

요청 > 웹 페이지 수집요청에서 주요 URL을 제출합니다.

- **실시간이 아닙니다.** 최소 1일에서 몇 주가 걸립니다.
- 공식 안내: *"동일 URL에 대해 매일 반복적으로 수집요청을 제출할 필요는 없습니다."*
- 인위적 반복 요청보다 검색로봇의 자연스러운 수집이 권장됩니다.

### 2-5. IndexNow (선택, 갱신이 잦다면 권장)

1. 8~128자 hex 문자열(`a-f`, `A-F`, `0-9`, `-`)을 키로 정합니다.
2. `site.config.mjs`의 `indexNowKey`에 넣고 배포하면 `/{key}.txt` 파일이 자동 생성됩니다.
3. 콘텐츠 갱신 시 통지:
   ```
   GET https://searchadvisor.naver.com/indexnow?url=<변경된URL>&key=<KEY>
   ```
   POST JSON 방식은 1회 최대 10,000 URL까지 가능합니다.

> 통지는 로봇 방문을 기다리지 않고 갱신을 알리는 수단일 뿐, **색인을 보장하지 않습니다.**

## Phase 3. 페이지 마크업 — ✅ 코드에 반영 완료

| 요건 | 네이버 기준 | 구현 |
|---|---|---|
| `<title>` | 페이지별 고유, 40자 이내 권장, 1개만 | ✅ 자동 생성 + `check-seo.mjs`가 길이·중복 검사 |
| `description` | 페이지별 고유, 80자 이내 권장 | ✅ `shortDescription()`이 80자로 자동 축약 |
| `<h1>` | 페이지당 1개 | ✅ 검사기가 강제 |
| `canonical` | **절대경로** | ✅ 전 페이지 |
| Open Graph | title·description·image·url | ✅ 전 페이지 |
| `og:image` | 150px 초과, 5KB 이상, 가로세로 3:1 이내 | ✅ 1200×630 PNG (약 212KB, 1.9:1) |
| 파비콘 | **절대경로**, rel 중복 없음, 16px 이상 정사각 | ✅ `shortcut icon` 단일 지정 |
| viewport | 반응형 | ✅ `width=device-width` |
| 이미지 `alt` | 전 이미지 | ✅ 검사기가 강제 |
| 내부 링크 | `<a href>` 형태 (JS 링크 불가) | ✅ 전부 표준 앵커 |

> `description`과 `og:description`을 다르게 두었습니다. 네이버는 둘이 다르면 색인 과정에서
> **검색에 더 적합한 값을 자동 선택**합니다. 검색결과용은 80자로 짧게, 공유 카드용은 전문으로 내보냅니다.

### 쓰면 안 되는 네이버 전용 태그

노출을 스스로 막는 태그이므로 **넣지 마세요.** 검사기가 발견 시 경고합니다.

| 태그 | 효과 |
|---|---|
| `<meta name="robots" content="nosourceinfo">` | AI 사이트 브리핑 출처 설명에서 제외 |
| `<meta name="naver" content="nosublinks">` | 서브링크 전체 노출 제외 |
| `<a rel="nosublink">` | 개별 서브링크 제외 |

## Phase 4. 구조화 데이터 — ✅ 코드에 반영 완료

네이버는 구조화 데이터를 **공식적으로 파싱합니다.** (Microdata 또는 JSON-LD 권장)
단, *"정상적으로 마크업했더라도 검색결과 반영을 보장하지 않습니다."*

| 스키마 | 적용 페이지 | 목적 |
|---|---|---|
| `Organization` + `InsuranceAgency` | 전 페이지 | 사이트 주체 식별 |
| `WebSite` | 전 페이지 | 사이트 단위 엔티티 |
| `BreadcrumbList` | 카테고리·게시글·용어집 | 검색결과 경로 표시 |
| `Article` | 게시글 | 문서 메타(작성일·수정일·저자) |
| `FAQPage` | 게시글·용어집·홈·카테고리 | 답변 엔진 인용 |
| `HowTo` | 절차형 게시글 | "~하는 방법" 질의 대응 |
| `DefinedTerm` / `DefinedTermSet` | 용어 사전 | "○○이란?" 정의형 질의 |
| `Service` | 카테고리 | 무료 상담 제공 명시 |

### 🙋 사람이 해야 함 — 사이트 연관채널

네이버가 가장 실용적으로 활용하는 항목입니다. 운영 중인 공식 채널을 `site.config.mjs`의
`sameAs`에 넣으면 `Organization` 스키마에 자동 연결됩니다.

```js
sameAs: [
  'https://blog.naver.com/<아이디>',
  'https://smartstore.naver.com/<스토어>',
  'https://www.instagram.com/<아이디>',
  'https://www.youtube.com/@<채널>',
],
```

지원 채널: 네이버TV·블로그·스마트스토어·지식iN·치지직 / 당근·스레드·인스타그램·유튜브·
카카오스토리·카카오톡채널·티스토리·틱톡·페이스북·X.

> **운영하지 않는 채널을 적지 마세요.** 실재하지 않는 연결은 신뢰도에 해가 됩니다.

## Phase 5. 콘텐츠 품질 — 지속 관리

네이버 공식 콘텐츠 5원칙(2026년 기준)입니다. 이 사이트의 게시글은 이 기준에 맞춰 작성되었습니다.

| 원칙 | 내용 | 이 사이트의 적용 |
|---|---|---|
| ① 전문성·직접 경험 | 실제 경험·공식 통계·연구 인용 | 각 글의 `facts`에 법령·감독기관 출처 명시 |
| ② 일관된 주제 | 전체 콘텐츠의 절반 이상이 핵심 주제 | 전 콘텐츠가 보험 단일 주제 |
| ③ 진정성·투명성 | 출처 표기, 경제적 대가 명시, AI 생성물 그대로 게시 금지 | 광고 페이지임을 푸터에 명시, 각 글에 면책 고지 |
| ④ 읽기 쉬운 구조 | 소제목·문단·번호, **핵심 정보는 본문 텍스트로** | 질문형 H2 + 목차 + 비교표, 이미지 의존 없음 |
| ⑤ 최신성 | 가격·정책·법규 갱신, 스팸 방치 금지 | 각 글 `updated` 필드가 `dateModified`로 반영 |

> 네이버는 특정 주제를 지속 발행하는 사이트를 **"해당 분야의 전문 출처"로 인식**합니다.
> 보험 외 주제를 섞지 마세요.

### 랭킹 관련 공개된 사실

- **뉴럴 매칭** (2024-04 업데이트): 문서 전체 주제까지 학습 → *"주제의 일관성을 지닌 문서의 검색 노출이 유리"*
- **신뢰도 중심 통합 랭킹 모델** (2025-11~): 웹·블로그·카페·지식iN·동영상이 **하나의 영역에서 함께 노출**되며,
  출처의 공신력·공식성·전문성으로 순위를 판별. 외부 사이트도 블록형 결과에 진입 가능한 구조로 이동 중.
- **AI 사이트 브리핑**: 사이트 제목·본문 등 메타 정보를 바탕으로 출처 설명을 자동 생성.
- **서브링크**: 사이트 구조를 자동 분석해 노출되며 **요청으로 추가할 수 없습니다.**
  표준 링크·앵커텍스트·GNB·사이트맵 품질이 추출 결과를 좌우합니다.

### 확인되지 않은 것 (추측 금지)

시중에 널리 퍼진 다음 항목들은 **네이버 1차 출처로 확인되지 않았습니다.**

| 항목 | 상태 |
|---|---|
| D.I.A / D.I.A+ 로직 | 네이버 공식 문서에 등장하지 않음. 시중 설명은 전부 2차 출처 |
| C-Rank의 외부 웹사이트 적용 | 공식 정의는 **블로그 출처 평가**. 웹마스터 가이드에 미등장 |
| 외부 사이트의 스마트블록 편입 조건 | 웹마스터 가이드에 "스마트블록" 미등장 |
| 페이지 속도·Core Web Vitals의 랭킹 반영 | 미확인. 수집 실패 임계값(1분·4MB)만 명시 |
| HTTPS의 직접적 랭킹 가점 | 미확인. 우선 수집·권장 사항으로만 명시 |

## Phase 6. 절대 하면 안 되는 것 (스팸 판정)

네이버 공식 스팸 유형입니다. 제재는 **노출 제외 또는 순위 하락**이며,
*"정상 운영되던 사이트라도 확인된 시점 이후 노출이 제한될 수 있습니다."*

**기술적 조작**
- 클로킹(사용자와 검색엔진에 다른 내용 제공, UA·레퍼러 기준 분기 포함)
- 부적절한 리다이렉트(일정 시간 후 이동, 뒤로가기 시 이동 포함)
- 링크 스팸, **백링크 인위적 대량 생성 후 사이트 판매** (판매 사이트와 포워딩 대상 모두 제재)
- 만료 도메인 악용, 매크로·트래픽 조작, 해킹된 콘텐츠, 악성코드

**콘텐츠 조작**
- 숨겨진 텍스트, **키워드 반복·남용**(title·description 내 2회 이상 반복이 구체적 불이익 기준)
- 낚시성 제목, **저품질 콘텐츠 대량 생성**(동일 템플릿·문장 일부만 변경한 페이지 수십 개 이상)
- 스크래핑(자동 복사·기계적 변형)

> **AI 활용 여부만으로는 스팸으로 판단하지 않습니다.** 판단 기준은 결과물의 품질과 행위 양태입니다.
> 다만 AI 생성물을 검토 없이 그대로 올리는 것은 ③ 진정성 원칙 위반입니다.

**추가 명시 불이익**
- 동일 콘텐츠로 여러 사이트 개설
- 검색 노출만을 위한 잦은 title·description 변경
- 상위 노출 목적의 동일 앵커텍스트·alt 텍스트 반복
- 사이트 방치로 게시판이 스팸 도배

구제: 시정 후 서치어드바이저 **[검색 노출 제보하기]** 로 사실관계와 시정 내역을 첨부해 요청.

## 부록. 이 사이트의 자동 검증

```bash
npm run build   # 정적 사이트 생성
npm run check   # SEO/AEO 요건 자동 검사 (실패 시 배포 중단)
```

`scripts/check-seo.mjs`가 검사하는 항목:

- title 길이(40자)·중복, description 길이(80자)·중복
- canonical 절대경로, `<html lang>`, viewport, H1 1개
- 파비콘 절대경로 및 rel 중복
- OG 5종, Twitter 카드
- JSON-LD 파싱 가능 여부 및 필수 스키마(Article·FAQPage·BreadcrumbList) 존재
- 이미지 alt 누락
- 상담 폼과 개인정보 동의 체크박스 존재
- 주민등록번호 수집 필드·문구 부재
- `sitemap.xml`·`robots.txt`·`rss.xml`·`llms.txt` 생성 및 사이트맵 URL 누락
- 노출을 막는 네이버 전용 태그(`nosourceinfo`·`nosublinks`) 오설정

GitHub Actions는 배포 전 이 검사를 실행하며, 실패하면 배포가 중단됩니다.
