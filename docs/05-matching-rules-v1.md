# 담보 매칭 엔진 규칙 테이블 v1 — 실손 1~4세대 파라미터

> **주의**: 아래 값은 표준약관 기반의 v1 근사치이며, 회사·상품·특약별 편차가 있다.
> 전 파라미터는 `core.matching_parameters` 테이블로 외부화되어 관리자 UI에서 수정 가능하며,
> 룰 버전(`rule_version`)이 모든 매칭 결과에 기록된다. 값 확정 전 손해사정사 검수 필수.
> 판단이 갈리는 케이스는 금액을 내지 않고 `UNDETERMINED`("전문가 검토 추천")로 라벨링한다.

## 1. 세대 판정 (가입일 기준 자동 태깅)

| 세대 | 가입 기간 | 특징 |
|---|---|---|
| 1세대 (구실손) | ~2009.09 | 표준화 이전. 회사별 상이(자기부담 0% 상품 다수). **판단불가 비율 높음** |
| 2세대 (표준화) | 2009.10 ~ 2017.03 | 표준약관. 입원 10%(선택형 20%), 통원 정액 공제 |
| 3세대 (신실손) | 2017.04 ~ 2021.06 | 기본형(급여 10%/비급여 20%) + 3대 비급여 특약(30%) |
| 4세대 | 2021.07 ~ | 급여 20% / 비급여 30%, 비급여 특약 분리, 할인·할증 |

## 2. 공제 파라미터 테이블 v1

계산식(공통): `예상 환급액 = max(0, 대상금액 − 공제액)`, `공제액 = max(정액공제, 대상금액 × 자기부담률)`, 회당 한도 상한 적용.

회당 한도 적용 단위: **1~3세대는 급여+비급여 통합 담보이므로 합산액에 한도를 1회 적용**하고, **4세대는 급여/비급여 담보가 분리되므로 파트별로 적용**한다. 한도가 발동하면 산출 근거 수식에 `min(한도, 합산액)` 항을 포함한다.

### 2.1 통원 (OUTPATIENT)

| 세대 | 구분 | 정액공제(의원/병원/종합/상급) | 자기부담률 | 회당 한도(기본) | 비고 |
|---|---|---|---|---|---|
| 1 | 통합 | 5,000 (일괄) | 0% | 100,000 | 회사별 상이 → 담보 데이터 없으면 UNDETERMINED |
| 2 | 통합 | 10,000 / 15,000 / 15,000 / 20,000 | 0% | 250,000 | 처방약제 별도 8,000 공제 |
| 3 | 급여+비급여(기본형) | 10,000 / 15,000 / 15,000 / 20,000 | 10%(급여)·20%(비급여) | 250,000 | 특약 대상 비급여는 30% |
| 4 | 급여 | 10,000 / 10,000 / 20,000 / 20,000 | 20% | 200,000 | |
| 4 | 비급여 | 30,000 (일괄) | 30% | 200,000 | 상급·종합 급여 공제 20,000 |

### 2.2 입원 (INPATIENT)

| 세대 | 구분 | 정액공제 | 자기부담률 | 연간 한도(기본) |
|---|---|---|---|---|
| 1 | 통합 | 0 | 0% (일부 상품 20%) | 상품별 |

|---|---|---|---|
| 1 | (통원에 포함, 상품별) | — | — |

## 3. 판정 로직

```
입력: 진료건(진료일, 요양기관 tier, 본인부담금 급여/비급여, 청구유형, 처방 여부)
      × 실손계약(세대, 자기부담률 오버라이드, 한도, 공제)

1. 계약 없음 / 실손 아님                        → NOT_CLAIMABLE
2. 진료일이 보장기간 밖                          → NOT_CLAIMABLE
3. 소멸시효(진료일+3년) 경과                     → NOT_CLAIMABLE (사유: statute_expired)
4. 세대 미상 / 1세대인데 담보 데이터 없음         → UNDETERMINED ("전문가 검토 추천")
5. 파라미터 조회 실패                            → UNDETERMINED
6. 계산: covered/uncovered 각각
     공제 = max(정액공제[tier], 대상금액 × 자기부담률)
     환급 = max(0, 대상금액 − 공제), 회당 한도 상한
   합산 결과 0원                                → NOT_CLAIMABLE (사유: below_deductible)
   합산 결과 > 0                                → CLAIMABLE + 산출 근거 문자열
```

산출 근거 문자열 예:
`"3세대 통원(급여): 48,000 − max(15,000, 48,000×10%) = 33,000 [rule silson-v1]"`

## 4. 정확도 개선 루프

- 지급 완료 시 사용자가 입력한 실지급액(`claims.actual_paid_amount`)과 예측치를 비교.
- 관리자 오차 대시보드: 세대별·청구유형별 오차율 집계, 목표 ±20% 이내.
- 오차 원인 상위 케이스는 파라미터 보정 → 새 `rule_version` 발행(기존 결과는 재계산하되 이력 보존).

## 5. 표기 정책과의 연결 (재확인)

- `CLAIMABLE` 결과만 금액 노출, 항상 "예상" 접두 + 산출 근거 펼침 + 면책 문구.
- `UNDETERMINED` 는 금액 미표기, "검토 필요" 라벨만.
- 확정액(숨은보험금)은 이 엔진을 거치지 않으며 별도 테이블·별도 API로 처리한다.
